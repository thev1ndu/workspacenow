# Flux deployment

One cluster, one environment, fully managed by Flux from this repo: no manual `kubectl apply`.
The layout follows numbered layers (the same idea as `init/layer-0..3` in the WSO2 cloud deployment
repo): each layer only uses CRDs and services from the layers before it, and Flux applies them in
order, each waiting until the previous one is ready.

```
deploy/flux/
├── cluster/                    # what the flux-system Kustomization syncs
│   ├── flux-system/            # bootstrap manifests (generated by flux, do not edit)
│   ├── cluster-vars.yaml       # THE file to edit: domain, gateway IP, issuer, git source, image tag, branding
│   ├── kustomization.yaml
│   └── 00-foundation.yaml … 04-apps.yaml   # one Flux Kustomization per layer (dependsOn the previous)
├── layers/
│   ├── 00-foundation/          # namespaces, HelmRepositories, CloudNativePG / External Secrets / OpenBao operators, kgateway CRDs + controller + GatewayClass, metallb pool
│   ├── 01-secrets-data/        # OpenBao setup Job, ClusterSecretStore, ExternalSecrets, the wsn-db Postgres cluster
│   ├── 02-services/            # NATS (JetStream), Valkey, RustFS object storage, Temporal (on wsn-db)
│   ├── 03-platform/            # kgateway Gateway + TLS certs, in-cluster OCI registry, kaniko image builds, node /etc/hosts pin
│   └── 04-apps/                # wsn-service (API, relay, worker, migrate job, backup), wsn-ai-service, wsn-observer, console, HTTPRoutes, NetworkPolicies
└── scripts/
    └── openbao-seed.sh         # puts the real secret values into OpenBao
```

## Cluster variables

Every layer runs Flux variable substitution (`postBuild.substituteFrom: ConfigMap cluster-vars`), so
`${domain}` etc. in the manifests come from `cluster/cluster-vars.yaml`:

| Variable | Current value | Used for |
|---|---|---|
| `domain` | `workspace.twotakeone.com` | console at `domain`; `api.`, `ai.`, `obs.`, `registry.` under it (gateway listeners, certs, HTTPRoutes, CORS, console `apiBaseUrl`, image names) |
| `gateway_ip` | `169.58.222.25` | metallb pool for the gateway; registry pin for kubelet and kaniko |
| `cluster_issuer` | `letsencrypt-dns` | cert-manager ClusterIssuer for the gateway certs (must already exist) |
| `git_repo` / `git_branch` | `github.com/thev1ndu/workspacenow.git` / `main` | what the kaniko Jobs build |
| `image_tag` | `dev` | tag the builds push and the apps pull from `registry.${domain}` |
| `org_name` | `WorkspaceNow North` | console branding |

Secrets never go here; they live in OpenBao (below). CI fails if a layer uses a `${var}` that
`cluster-vars.yaml` does not define. A manifest that needs literal shell `${...}` (the
`openbao-config` Job) carries `kustomize.toolkit.fluxcd.io/substitute: disabled`.

| Service | Hostname | Backend |
|---|---|---|
| Console | `${domain}` | console:8080 |
| Platform API | `api.${domain}` | wsn-service:8080 |
| AI service / MCP | `ai.${domain}` | wsn-ai-service:8090 |
| Observer | `obs.${domain}` | wsn-observer:9098 |
| OCI registry | `registry.${domain}` | registry:5000 (TLS at the gateway) |

## Deploy

Prerequisites already on the cluster: Flux CLI access, metallb, cert-manager with the
`cluster_issuer` ClusterIssuer. Everything else is installed by layer 00.

1. **DNS**: one DNS-only wildcard record `*.${domain}` A → `gateway_ip` (it also covers `${domain}`).
2. **Edit** `cluster/cluster-vars.yaml` if anything differs, commit, push.
3. **Bootstrap** (once per cluster):

   ```sh
   export KUBECONFIG=kube.conf
   flux bootstrap github --owner=thev1ndu --repository=workspacenow --branch=main \
     --path=deploy/flux/cluster --personal --token-auth <<< "$GITHUB_TOKEN"
   ```

4. **Secrets**: the `openbao-config` Job (layer 01) enables Kubernetes auth, creates the
   `external-secrets` and `wsn-service` roles and seeds placeholder values. Put the real ones in:

   ```sh
   OPENBAO_ROOT_TOKEN=root MISTRAL_API_KEY=... AI_SERVICE_TOKEN=... OBSERVER_TOKEN=... \
     RUN_GRANT_PRIVATE_KEY=... OBJECT_STORAGE_ACCESS_KEY=... OBJECT_STORAGE_SECRET_KEY=... \
     TEMPORAL_DB_PASSWORD=... WSN_DEFAULT_ADMIN_EMAIL=... WSN_DEFAULT_ADMIN_PASSWORD=... \
     ./deploy/flux/scripts/openbao-seed.sh
   ```

   | OpenBao path `secret/workspacenow/...` | Keys | Lands in |
   |---|---|---|
   | `mistral` | `apiKey` | Secret `wsn-secrets` → `MISTRAL_API_KEY` |
   | `ai-service` | `token` | `wsn-secrets` → `AI_SERVICE_TOKEN` |
   | `observer` | `token` | `wsn-secrets` → `OBSERVER_TOKEN` |
   | `run-grant` | `privateKey` (base64 Ed25519 seed) | `wsn-secrets` → `RUN_GRANT_KEY` |
   | `object-storage` | `accessKey`, `secretKey` | `wsn-secrets` (`S3_*`) + `wsn-rustfs-env` (RustFS) |
   | `temporal-db` | `password` | `temporal-db-login` (wsn-db role) / `temporal-db` (Temporal) |
   | `default-admin` | `email`, `password` | `wsn-secrets` → `WSN_DEFAULT_ADMIN_EMAIL` / `WSN_DEFAULT_ADMIN_PASSWORD` |

   OpenBao runs in dev mode (in-memory): after an OpenBao pod restart, re-run the seed script.

5. **Watch** the layers come up in order:

   ```sh
   flux get kustomizations                                 # 00-foundation … 04-apps, all Ready at one revision
   kubectl -n workspacenow get jobs | grep build           # in-cluster image builds
   kubectl -n workspacenow get pods,gateway,httproute,certificate
   curl -s https://api.${domain}/healthz | jq              # postgres, valkey, nats, temporal, object storage, openbao, ai-service, observer
   ```

## Images

Layer 03 runs one kaniko Job per component (`builds.yaml`), building its `Dockerfile` from
`git_repo`@`git_branch` and pushing `registry.${domain}/<component>:${image_tag}`. Build pods pin the
registry hostname to `gateway_ip` through `hostAliases`; the `registry-host-alias` DaemonSet writes the
same pin into each node's `/etc/hosts` so kubelet pulls work. App containers use
`imagePullPolicy: Always`, so a rebuild rolls out on the next pod restart.

```sh
kubectl -n workspacenow logs -l job-name=build-wsn-service -f
kubectl -n workspacenow delete job build-wsn-service          # rebuild one: Flux re-creates the Job
kubectl -n workspacenow rollout restart deploy/wsn-service     # pick up the new image
```

`.github/workflows/images.yaml` also publishes the same images to `ghcr.io/thev1ndu` for compose
(`make up`).

## Sign in

The console offers system-user sign-in (`authMode: "local"`); the user comes from
`secret/workspacenow/default-admin` and gets the `workspacenow-admin` role on first login:

```sh
PW=$(kubectl -n openbao exec statefulset/openbao -- sh -c \
  'bao login root >/dev/null && bao kv get -field=password -mount=secret workspacenow/default-admin')
curl -s -X POST https://api.${domain}/api/v1/auth/login -H 'Content-Type: application/json' \
  -d "{\"email\":\"admin@workspacenow.local\",\"password\":\"$PW\"}" | jq -r .token
```

For OIDC, set `OIDC_ISSUER` / `OIDC_AUDIENCE` / `OIDC_JWKS_URL` and `WSN_BOOTSTRAP_ADMIN_EMAILS` in the
`wsn-service` ConfigMap (`layers/04-apps/wsn-service.yaml`) and `authMode: "oidc"` plus an `oidc`
block in the `console` ConfigMap (`layers/04-apps/console.yaml`).

## Data safety

Namespaces, the `wsn-db` Cluster and the PVCs (`rustfs-data`, `registry-data`, `wsn-observer-data`)
carry `kustomize.toolkit.fluxcd.io/prune: disabled`: deleting them from git (or renaming a layer)
never deletes the data. Remove them by hand if you really mean it.

## Migrating the running cluster from the old layout

The cluster was bootstrapped at `deploy/flux/clusters/dev` with the Kustomizations `infra-controllers`,
`infra-configs`, `infra-temporal`, `platform` and `workspacenow`. The new layers own the same 87
objects with identical specs. Suspend the old Kustomizations first, so that Flux deleting them
does not garbage-collect what they applied, then switch the sync path:

```sh
export KUBECONFIG=kube.conf
flux suspend kustomization infra-controllers infra-configs infra-temporal platform workspacenow
git push                                                    # this layout
kubectl -n flux-system patch kustomization flux-system --type merge \
  -p '{"spec":{"path":"./deploy/flux/cluster"}}'
flux reconcile kustomization flux-system --with-source
flux get kustomizations                                     # old five gone, 00-foundation … 04-apps Ready
```
